---
title: "OAuth Flow"
description: "How Majarrah's MCP server authenticates AI clients."
---

Majarrah implements the OAuth 2.1 subset of the MCP authorization spec, including PKCE, Dynamic Client Registration (RFC 7591), Authorization Server Metadata (RFC 8414), and Protected Resource Metadata (RFC 9728). If your MCP client follows the spec, it should just work — the details below are for engineers integrating custom clients or auditing what happens when you click "Authorize".

## Endpoints

- **Resource metadata**: `https://api.majarrah.io/.well-known/oauth-protected-resource`
- **Authorization server metadata**: `https://api.majarrah.io/.well-known/oauth-authorization-server`
- **Dynamic client registration**: `https://api.majarrah.io/oauth/register`
- **Authorize**: `https://api.majarrah.io/oauth/authorize`
- **Token exchange**: `https://api.majarrah.io/oauth/token`
- **Token revocation**: `https://api.majarrah.io/oauth/revoke`

## Flow

<Steps>
  <Step title="Client registration">
    First-time clients POST to `/oauth/register` with a `client_name` and `redirect_uris`. They receive a `client_id` (public). No client secret — MCP relies on PKCE only.
  </Step>
  <Step title="Authorization request">
    Client redirects the user to `/oauth/authorize` with `client_id`, `redirect_uri`, `response_type=code`, `code_challenge`, `code_challenge_method=S256`, `state`, and `scope=mcp`.
  </Step>
  <Step title="User consent">
    Majarrah shows a role-scoped consent screen listing what the client can access. The user reviews and approves.
  </Step>
  <Step title="Code redemption">
    Client exchanges the returned `code` at `/oauth/token` with the matching `code_verifier` and receives an `access_token` + `refresh_token`.
  </Step>
  <Step title="MCP calls">
    Every request to `/mcp` includes `Authorization: Bearer <access_token>`. The server resolves the token to a user and mounts role-appropriate tools.
  </Step>
  <Step title="Token refresh">
    Access tokens expire after one hour. Clients use the refresh token at `/oauth/token` with `grant_type=refresh_token` to get a fresh one.
  </Step>
</Steps>

## Scopes

Majarrah currently exposes one scope: `mcp`. Tools available to the token are determined at request time by the user's platform roles, not by a scope string.

## Token storage

Access and refresh tokens live in the `mcp_access_tokens` table on Majarrah's backend, keyed by the token itself. Every call updates `last_used_at`. Revoking a token (via `/oauth/revoke`, from the user dashboard, or from a client's connector settings) sets `revoked_at` — subsequent bearer usage is rejected.

## Rate limits

- 60 authorization attempts per user per hour
- 300 MCP tool calls per token per hour
- 429 responses include `Retry-After` header

<Note>
  Static admin bearer tokens are also supported for programmatic access (CI, scripts). These bypass OAuth and require a shared secret configured server-side. Contact `support@majarrah.io` if you need one.
</Note>
